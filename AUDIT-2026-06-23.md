## 3. Nginx & Origin Issues

### 3.1 Missing Proxy Buffer Tuning

The nginx config has **no `proxy_buffer_size`, `proxy_buffers`, or `proxy_busy_buffers_size`** directives. This caused:

```
upstream sent too big header while reading response header from upstream
```

4 occurrences in `error.log`, triggered by maliciously long SQL-injection query strings on `/contact`.

**Fix:** Add to the server/location blocks:

```nginx
proxy_buffer_size 8k;
proxy_buffers 8 8k;
proxy_busy_buffers_size 16k;
proxy_temp_file_write_size 32k;
```

### 3.2 Nginx Rate Limiting

- `limit_req zone=botlimit burst=50 nodelay;` is active but not visible in config snippet; verify zone definition exists.

### 3.3 Cache Key

Cache key includes `$http_accept$http_authorization` — correct for markdown negotiation and paid API keys.

### 3.4 Duplicate Security Headers

`X-Content-Type-Options: nosniff` is emitted twice on some responses (nginx + Next.js).

## 4. SEO & Indexing

- Note: `X-Robots-Tag: noindex` is set on the robots.txt response itself (harmless).

### 4.2 Sitemap Index

- `sitemap_index.xml` lists 14 sub-sitemaps.
- Sitemaps are generated by prebuild scripts and refreshed.

### 4.3 Critical: Pre-1982 Vehicle URLs in Sitemap

**Issue:** `src/app/vehicles/sitemap.ts` generates URLs for every year in `VEHICLE_PRODUCTION_YEARS`, but `src/app/vehicles/[year]/[make]/[model]/page.tsx` returns `notFound()` for `yearNum < 1982`.

**Impact:**
- 527 pre-1982 URLs in `/vehicles/sitemap.xml` return 404.
- Site health monitor has failed every hour since 2026-06-21 because of this.
- Wastes crawl budget and trains search engines that the sitemap is unreliable.

**Fix:** In `src/app/vehicles/sitemap.ts`, skip years `< 1982`:

```ts
for (let year = range.start; year <= range.end; year++) {
  if (year < 1982) continue;
  // ...
}
```

- Content worker log shows successful IndexNow submissions for individual repair pages.

## 5. Codebase Audit

### 5.1 Critical Bugs

#### 5.1.1 Webhook Refund/Dispute Logging Broken

**File:** `src/lib/credits.ts:155`  
`creditCustomer()` throws if `amountCents <= 0`.

**File:** `src/app/api/stripe/webhook/route.ts:72`  
Calls `creditCustomer(customer.id, 0, ...)` for `charge.refunded` and `charge.dispute.created`.

**Result:** Refund/dispute events will always throw a 500, leaving no audit trail.

**Fix:** Either:
- Allow zero-amount transactions in `creditCustomer` for audit types, OR
- Use a separate `recordAuditEvent()` function for zero-amount events.

#### 5.1.2 Vehicle Sitemap vs Page Mismatch

(See section 4.3.)

### 5.2 High Issues

#### 5.2.1 Site Monitor Runs Duplicated

`/var/log/alloemmanuals-monitor.log` shows every log line duplicated at identical timestamps. Likely two monitor invocations overlapping or the script appending twice. Investigate cron/systemd double-trigger.

#### 5.2.2 `/api/v1/repair` Middleware Rewrite Uses Hardcoded `127.0.0.1:3002`

In `src/middleware.ts`, JSON requests to `/repair/...` are rewritten to `http://127.0.0.1:3002/api/v1/repair`. This bypasses the Cloudflare Worker and any edge bot policy. Acceptable for localhost, but should use configurable origin.

#### 5.2.3 Content-Security-Policy Allows Broad Third-Party Domains

CSP allows Google ad/tracking domains broadly. No immediate vulnerability, but surface area is large.

### 5.3 Medium Issues

#### 5.3.1 Worker Comment Numbering Duplicate

`deploy/cloudflare/worker.js` has two steps labeled `// ── 4.` (malicious bots and paywalled bots). Cosmetic only.

#### 5.3.2 402 Markdown Copy Inconsistency

- `paymentGate.ts` says "Human Site (Free for Browsers)".
- `worker.js` says "both are paid products".
- Pick one policy and align all copy.

#### 5.3.3 `.env.local.example` Still References TollBit

TollBit integration was replaced by x402/Stripe. Example file is stale and may confuse future setup.

#### 5.3.4 `creditCustomer` Amount Validation Too Strict

Zero-amount audit transactions are valid; should not throw.

### 5.4 Security Observations

- No hardcoded Stripe keys, Cloudflare keys, or DB passwords found in source.
- API keys are hashed with SHA-256; plaintext is cleared after first display.
- Origin shield (`$cloudflare_trusted`) blocks direct origin access.
- `X-Payment-Verified` header can be spoofed if request reaches origin without Worker, but origin shield mitigates.
